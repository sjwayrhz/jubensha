# jubensha 服务器部署手册

基于 clerk 真实部署经验编写（2026-10-08 上线）。界面/命令以实际为准。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 服务器 | clerk（Ubuntu 24.04，无公网 IP），hostname 为 `ubuntu` |
| Python | 3.14（venv 在 `/root/venvs/jubensha`，项目用 Python 3.14 实测） |
| Node | 构建前端用（本机有 Node 24；clerk 上未装，见第 6 节） |
| 出站网络 | 无直连外网，pip/npm/模型下载走宿主机代理 `http://192.168.56.1:7897` |
| 入站网络 | 走 cloudflared 隧道（见第 7 节） |

注意：`paddlepaddle` / `rapidocr_onnxruntime` 没有 Python 3.14 的 wheel，OCR 实际用 Tesseract（系统包 `tesseract-ocr` + `tesseract-ocr-chi-sim` 简体中文语言包）+ `pytesseract`。Tesseract 中文偶有误识，人工校对步骤不可省略。

## 3. .env 配置

`.env` 固定在**项目根目录**（`/root/jubensha/.env`），`config.py` 按绝对路径读取，与启动时的当前目录无关。

字段列表（只列字段名，不写真实值）：

```ini
TIDB_HOST=            # TiDB Cloud 主机
TIDB_PORT=4000
TIDB_USER=
TIDB_PASSWORD=        # 真实密码，只存这个文件
TIDB_DB=jubensha      # 独立 database，与 ludepress 共用集群
# TIDB_SSL_CA=        # TiDB Cloud 需要 TLS 时填 CA 证书路径
JWT_SECRET=           # 生产必须改，随机长字符串
JWT_EXPIRE_MINUTES=10080
UPLOAD_DIR=uploads
MAX_UPLOAD_MB=50
OCR_TEXT_THRESHOLD=200
```

硬要求：
- `chmod 600 /root/jubensha/.env`
- `.env` 已在 `.gitignore`，`git status` 里看不到才算对
- 真实密码/密钥只存这个文件，不进聊天、不进提交、不入记忆

## 4. TiDB Cloud

- 与 ludepress 共用集群，独立 database：`jubensha`
- clerk 可直连 TiDB 4000 端口（已验证）
- 表由 SQLAlchemy `Base.metadata.create_all` 在启动时建（以代码 models 为准）

## 5. 后端部署

```bash
# 1. 装依赖（走代理）
/root/venvs/jubensha/bin/pip install --proxy http://192.168.56.1:7897 -r /root/jubensha/backend/requirements.txt

# 2. systemd 服务（/etc/systemd/system/jubensha.service），以下为线上实际内容：
```

```ini
[Unit]
Description=jubensha script-murder web game
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/jubensha/backend
EnvironmentFile=/root/jubensha/.env
ExecStart=/root/venvs/jubensha/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 3. 生效并设开机自启
systemctl daemon-reload
systemctl enable --now jubensha

# 4. 本机验证
curl 127.0.0.1:8000/healthz   # 应返回 {"name":"jubensha","env":"dev","db_configured":true}
```

注意：`--host` 必须用 `0.0.0.0`（原因见第 7 节隧道坑）。

## 6. 前端构建与同步

clerk 上没有 Node，流程是**本机构建 → scp 同步**：

```bash
# 本机（有 Node 的机器）
cd ~/workspace/jubensha/frontend
npm install --proxy http://192.168.56.1:7897   # 如需代理
npm run build                                   # 产物在 frontend/dist（gitignored，不进仓库）

# 同步到 clerk
scp -r frontend/dist clerk:/root/jubensha/frontend/
```

后端 `backend/app/main.py` 自动托管 `frontend/dist`：
- `/assets/*` → 静态资源
- 其他非 `/api/*` 路径 → SPA fallback 到 `index.html`
- `/api/*` 不 fallback，照常 404
- 健康检查在 `/healthz`

前端改动后：本机重新 `npm run build` → scp 覆盖 → 无需重启后端（纯静态文件）。

## 7. cloudflared 隧道（重点，有坑）

- clerk 上的 cloudflared 以 **token 方式**跑在 docker 容器里（`tunnel --token … run`），**没有本地 config 文件**，ingress 规则在 Cloudflare 面板里配。
- 面板路径：Zero Trust → Networks → Tunnels → 找到该隧道 → Public Hostnames → Add：
  - Hostname：`jubensha.monk.de5.net`
  - Service URL：`http://172.17.0.1:8000`
- DNS 记录由面板自动创建，无需手动加。

### ⚠️ 两个 502 坑（2026-10-08 真实踩过）

1. **Service URL 填 `http://127.0.0.1:8000` 会 502**：cloudflared 容器是 docker bridge 模式，容器里的 `127.0.0.1` 指容器自身，到不了宿主机上的 uvicorn。
2. **`host.docker.internal` 在这台机器上不可用**：宿主机和容器内都解析为 NXDOMAIN（Linux 原生 Docker 默认不提供这个域名，容器启动时没加 `--add-host`）。填它同样 502。

正确做法：宿主机 uvicorn 绑 `0.0.0.0`（第 5 节的 unit 文件已是如此），面板 Service URL 填 `http://172.17.0.1:8000`（docker0 网关地址，`ip -4 addr show docker0` 确认）。验证网桥内可达：

```bash
docker run --rm busybox wget -qO- http://172.17.0.1:8000/healthz
```

## 8. 验证清单

按顺序执行，全过才算上线：

```bash
systemctl is-active jubensha                                   # active
curl -s 127.0.0.1:8000/healthz                                 # db_configured:true
curl -s -o /dev/null -w "%{http_code}\n" https://jubensha.monk.de5.net/   # 200
```

冒烟（注册→登录→鉴权，邮箱用正常域名，`.local` 等保留域名会被校验拒绝）：

```bash
curl -s -X POST https://jubensha.monk.de5.net/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"smoke@example.com","password":"test1234"}'
# 201；再用 /api/v1/auth/login 拿 token 调 /api/v1/auth/me 验证
```

注意：Cloudflare 会 403 掉 `Python-urllib/*` 的 UA，脚本里请设正常 User-Agent。

## 9. 日常运维

```bash
# 更新代码
cd /root/jubensha && git pull
# 前端有改动 → 本机 npm run build → scp 覆盖 frontend/dist
# 后端有改动 → systemctl restart jubensha

# 看日志
journalctl -u jubensha -f
systemctl status jubensha

# 改测试管理员密码（admin@jubensha.local / 上线前必须改）
# 暂无自助改密码接口：连 TiDB 直接更新 users 表的 password_hash（bcrypt 哈希）
```

## 10. 回滚与备份

- 回滚：`cd /root/jubensha && git reset --hard <上一个稳定commit> && systemctl restart jubensha`（前端 dist 如有变化同步用 scp 覆盖旧版）。
- 备份：TiDB Cloud 侧保留自动备份；`/root/jubensha/.env` 单独存一份在安全位置，丢了就得重建全部密钥。
